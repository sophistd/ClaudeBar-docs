## Platform

The package declares macOS 14 or later and Swift tools version 6.2. Build and fixture checks ran on Apple silicon Macs; Intel runtime behavior and a full macOS version matrix were not verified here.

## Browser model and engine families

| Browser engine tier | Known entries | Mode represented by the implementation | Fingerprint family and constraint |
| --- | --- | --- | --- |
| Pure Chromium | Chrome, Edge, Brave, Aside | Guarded sandbox or native session | `chromium` family; installed-app detection must confirm capability. Multiple profiles or sandboxes in the same family isolate cookies only, not hardware/rendering fingerprints |
| Gecko | Firefox, Zen (dynamic detection also covers LibreWolf, Waterfox, Floorp) | Guarded sandbox or native session | `gecko` family; uses `-no-remote -profile` with generated `user.js`. Crossing from Chromium to Gecko reduces browser-install fingerprint overlap |
| Wrapped Chromium shell | Arc, Dia | Native session | `chromium` family; do not assume Chromium launch flags or separate data-directory support |
| System WebKit | Safari | Native session | `webkit` family; Chromium command-line routing is unavailable |

This table describes code-supported modes, not a certification of every browser release. Deterministic `--profile-directory` subprofile routing is limited to pure Chromium browsers. If you must run multiple distinct Web accounts on one Mac, assign different engine families (for example, Chrome paired with Firefox or Zen); see [multi-account isolation and risk boundaries](/ClaudeBar-docs/guides/multi-account-isolation/).

## Proxy import versus transport

The following formats can be parsed; runtime use depends on the transport requirements.

| Input | Direct gate use |
| --- | --- |
| HTTP CONNECT | Supported after verification |
| SOCKS5 / SOCKS5H | Supported through the SOCKS path |
| HTTPS upstream proxy | Requires a local bridge; no silent TLS downgrade |
| Shadowsocks, VMess, VLESS, Trojan, Hysteria2, TUIC share formats | Encrypted remote transport requires a local core bridge |
| Supported Clash YAML entries | Depends on the resulting transport |

A loopback bridge must itself be configured and running. ClaudeBar's parser does not install a third-party network core.

## System-level controls

System-extension code exists, but a local build alone does not grant entitlements or OS activation. Packet-filter controls involve elevated permissions and affect a different boundary from an ordinary loopback listener. Neither was activated or tested during documentation work.
