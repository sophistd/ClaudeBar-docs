## What ClaudeBar is designed to control

The loopback gate manages connections routed through it. Based on the reviewed source baseline, ClaudeBar implements the following local controls:

- **Fail-closed managed egress gate**: preflight checks verify the exit through an isolated probe tunnel and record an egress baseline; multi-source country splits, IP drift, or uncovered critical observation gaps block launch or isolate the session.
- **Bypass-channel and locale alignment**: launch flags and local probes cover remote DNS, IPv6 bypass, UDP STUN, and QUIC (reported honestly as rule-based mitigation rather than packet capture when the host exposes public IPv6 or raw UDP), and align `TZ` and `LANG` / `LC_ALL` / browser locale with the exit country.
- **Local session and device-state isolation**: separate cookie and storage directories for supported browser sandboxes; isolated `CLAUDE_CONFIG_DIR` (`userID` in `~/.claude.json`) for Claude Code CLI; isolated data directories (`ant-did`) for Claude Desktop.
- **Read-only local auditing and journaled recovery**: zero-wake read-only probes such as `P15` (container collisions) and `P19` (`userID` / `ant-did` binding collisions, storing only SHA-256 hashes), paired with rollback-capable remediation.
- **Same-exit risk beacons without JS spoofing**: ClaudeBar intentionally does not block `s-cdn.anthropic.com` and does not inject UA, Canvas, or WebGL spoofing scripts; risk beacons travel over the same verified exit as the main session, while optional privacy mode only blocks configured third-party telemetry hosts.
- **Diagnostic redaction**: diagnostic exports apply redaction before writing an archive.

These are implementation descriptions, not a security certification or a promise against account bans.

## What ClaudeBar cannot control or guarantee

- **Same-engine browser fingerprint overlap**: separate profiles or `--user-data-dir` sandboxes within the same Chromium engine isolate cookies and storage, not hardware or graphics fingerprints (~74 of 79 observed Sift fields stay unchanged). See [multi-account isolation and risk boundaries](/ClaudeBar-docs/guides/multi-account-isolation/).
- **Inherent proxy-node reputation**: ClaudeBar cannot turn a datacenter, commercial VPN, or dirty IP into a clean residential exit (`P05` warns by default and can fail closed when `blockDatacenterASN` is enabled).
- **Provider fraud and identity graphs**: payment cards and Stripe Radar linkage, email/phone normalization linkage, Persona / Yoti identity verification, Sift's cross-merchant reputation graph, and whether a provider permits or suspends an account.
- **Traffic outside the managed path**: the loopback gate does not cover every process or packet on the machine; optional system extensions and packet-filter controls require separate entitlements, signing, notarization, and activation that are not verified in this documentation baseline.

ClaudeBar is intended for legitimate network configuration, session management, and diagnostics. Provider terms and account rules still apply.

## Local data, exports, and external exposure

Profiles store settings and credential references. Secrets are intended to be stored through the macOS Keychain path rather than directly in normalized proxy configuration, and device-identity bindings store SHA-256 hashes only. Local diagnostics and history can still reveal environment details.

Account masking is a display aid, not encryption. Redaction reduces disclosure; it does not remove the need to inspect a diagnostic archive before sharing it. Never publish a real profile store, browser data directory, account identifiers, or signing material.

While signed into `claude.ai`, page navigation sends the full URL (including conversation UUID), the start of the conversation title, and the account UUID to Sift in plaintext. Do not place secrets, tokens, or real names in conversation titles.

## Optional prompt analysis

Prompt-preflight cloud stages may transmit text to the configured provider. Check the selected provider and workflow before submitting confidential content. This documentation site has no AI chat service and does not call a model provider.

## Report a concern

Contact the project maintainer through the private channel used to obtain source access or the build. Do not post credentials, private diagnostics, or exploit details in a public documentation issue. A dedicated public vulnerability-reporting address has not been established in the reviewed baseline.

ClaudeBar is independent and is not affiliated with or endorsed by Anthropic.
