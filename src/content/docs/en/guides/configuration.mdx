## Open the profile settings

In **档案与设置** (Profiles & settings), select the intended profile. Use a descriptive local name. Do not treat a profile name as proof of the account currently signed into a browser.

## Import the upstream

Use the proxy import UI for your endpoint or supported share format. The parser distinguishes two outcomes:

- A direct HTTP CONNECT or SOCKS5 route can be used by the gate.
- HTTPS upstream proxies and encrypted share protocols need an appropriate local core bridge. Import the protocol into your authorized local core, then select its supported loopback proxy listener.

After import, the route must still pass preflight. See [compatibility](/ClaudeBar-docs/reference/compatibility/).

## Choose session behavior

Open **浏览器** (Browser), select an installed application, then choose the allowed session mode (both pure Chromium browsers and Gecko browsers such as Firefox and Zen support guarded sandboxes). When a native browser exposes supported subprofiles, choose the intended **子容器** (subprofile) and resolve any collision warning.

If you manage multiple **distinct** Web accounts on one Mac, do not assign them to multiple subprofiles or sandboxes of the same Chrome installation. Prefer isolated CLI or assign one browser engine family per Web account (for example, Chrome paired with Firefox or Zen). See [multi-account isolation and risk boundaries](/ClaudeBar-docs/guides/multi-account-isolation/).

## Review recovery, ASN, and isolation controls

Keep strict IP pinning unless your operating requirements justify a different recovery predicate. The default grace window is four seconds; it is a hold window, not a promise that every request survives an interruption.

- **Datacenter ASN blocking (`blockDatacenterASN`)**: off by default (`P05` warns on datacenter or commercial VPN ASNs). Enable it if you want datacenter or missing-ASN exits to fail closed.
- **CLI directory isolation (`isolateClaudeConfigDir`)**: assigns a per-profile `CLAUDE_CONFIG_DIR` so each profile keeps its own `~/.claude.json` `userID`. Multi-channel profiles enable this by default; legacy single profiles can enable it explicitly.
- **Telemetry mode**: applies to the managed path. `s-cdn.anthropic.com` risk beacons are forwarded over the same verified exit rather than blocked; `officialPrivacyFlags` only blocks configured third-party telemetry hosts. The enterprise-cloud enum is represented in configuration, but its label alone does not prove end-to-end provider integration. See [configuration reference](/ClaudeBar-docs/reference/configuration/).

## Verify the result

Run the current profile's checks, review unresolved findings and the live Protection Receipt card (including any `H17` same-engine overlap warning), and use the verified launch action. Confirm the resulting managed session rather than relying on a pre-existing browser window.
