## 连接和会话问题

| 你看到的现象 | 先看哪里 | 怎么处理 |
| --- | --- | --- |
| 门禁一直无法就绪 | 关键失败项，以及缺少补偿措施的 `UNOBSERVED` 项 | 处理前置条件，重新跑启动前检查 |
| 代理能导入，但连不上 | 导入结果和代理协议 | 如果要求转接，配置受支持的本地代理内核 |
| 已打开的浏览器登录了别的账号 | 会话模式和绑定的容器 | 选一个受支持的独立容器。当前窗口的登录状态请到浏览器里确认 |
| 原生浏览器与门禁看到的出口不同 | 本机出口和门禁出口的对照结果 | 启动前核对网络设置，确认两条路径各自该走哪里 |
| 切换网络后会话暂停 | 门禁是否处于 `GRACE_HOLD`，以及事件时间线 | 在宽限期内等出口匹配后恢复。如果已经隔离，查看隔离原因 |
| 服务提供方拒绝了请求 | 目标服务的响应和上游代理的连通性 | 根据响应查请求或服务侧原因，同时用连通性结果判断线路是否可达 |
| 系统扩展不可用 | 签名、entitlement、扩展激活和 macOS 批准状态 | 按授权版本附带的部署说明操作 |

## 源码构建失败

记录源码的确切版本、工具链、运行的命令，以及编译器报出的第一条错误。站点和应用各有自己的构建检查。实际跑过哪些应用构建和用例、还有哪些发布验证待做，见[基线与验证状态](/ClaudeBar-docs/zh/project/status/)。

## 需要维护者协助时

写清应用或构建版本、macOS 版本、你原本要做什么、实际状态和复现步骤。如果要附诊断包，先审阅内容。公开问题里只放去掉凭据、账号和会话数据后的信息。
