## 现在可以等，还是要重新核验？

网络短暂中断后，门禁可能正在宽限期内等待。它会根据这段时间拿到的结果决定下一步。

| 发生了什么 | 门禁怎么处理 |
| --- | --- |
| 宽限期内确认出口身份仍符合基线 | 恢复放行 |
| 宽限期结束时，只有观测缺失，且没有恢复探测被拒绝的记录 | 沿用旧的出口基线恢复放行，出口尚未得到新的核验 |
| 已记录恢复探测被拒绝，直到宽限期结束仍未恢复 | 进入隔离 |

一旦隔离，需要查看这次事件并重新核验。单纯等待或重新打开目标网站无法解除隔离。

到 **复盘** 和 **检查与修复** 核对当前档案，找到第一项失败的观测。看它指向的是连通性问题、出口发生变化、会话冲突，还是配置问题。

## 先看修复会做什么

```sh
swift run claudebar-cli fix --dry-run --json
```

预演会检查实时环境、列出修复方案，并跳过实际修复操作。它仍可能访问网络端点、读取凭据，并初始化诊断记录库。先看各项修复动作的影响和所需权限。

## 只执行对得上原因的那项修复

命令格式为 `claudebar-cli fix --apply Rxx --json`。把 `Rxx` 换成此次预演结果里的实际动作 ID。需要更高权限的动作须单独开启对应选项，并先确认操作确实需要这些权限。

修复流程会记下一份状态快照，执行动作，再跑相关检查。如果复查没过，流程可能回滚。看返回状态，确认这次修复是否通过复查。

## 需要撤销时，用修复日志里的快照

```sh
swift run claudebar-cli undo --latest --json
```

这条命令会用符合条件的快照恢复本地状态。运行前确认要撤销的是哪笔操作。要指定一笔记录，使用该记录的 UUID。撤销范围以快照记录的内容为限，外部系统的改动或未记录的操作要另行处理。

## 确认会话恢复

重跑相关检查，从经过核验的入口重新启用门禁，然后确认当前档案和受管会话。问题仍在时，留好脱敏后的观测结果，顺着失败项继续查原因。
