## 选中要设置的档案

在侧栏底部的 **Settings**（偏好设置，页面标题「系统偏好与档案」）里选中目标档案，用一个容易辨认的名字保存。要确认登录的是哪个账号，打开实际的浏览器会话查看。

## 代理能直接用，还是需要转接？

在应用里导入代理地址或受支持的分享链接。看导入结果，需要做的事分两种。

- **HTTP CONNECT 或 SOCKS5**：门禁支持直接使用这两种协议。
- **HTTPS 上游代理或加密分享协议**：把配置导入有权使用的兼容本地代理内核，再在 ClaudeBar 里选该内核提供的、门禁支持的回环代理端口。

导入成功后，线路仍须通过启动前检查。具体支持范围见[兼容性](/ClaudeBar-docs/zh/reference/compatibility/)。

## 选定会话实际使用的浏览器

打开 **浏览器**，选一个已安装的应用，再选它支持的会话模式（纯 Chromium 与 Gecko 浏览器如 Firefox / Zen 均支持单独打开沙箱）。如果原生浏览器提供受支持的独立档案，可在 **子容器** 中选定这次要用的档案。看到容器冲突提示时，先处理冲突。

如果一台 Mac 上要配置多个**不同** Web 账号，不要把它们都绑到同一个 Chrome 的不同子容器或不同沙箱里；应优先用隔离后的 CLI，或按“一核一号”分配不同内核的浏览器（例如 Chrome 搭配 Firefox / Zen）。完整优先级和原因见[多账号隔离与风控边界](/ClaudeBar-docs/zh/guides/multi-account-isolation/)。

## 看看网络变化、ASN 与隔离选项

默认保持严格固定 IP。只有确实需要按不同条件恢复时，再调整这项设置。默认宽限期为 **4 秒**。新连接的握手在这段时间内等待恢复；已有连接是否断开，取决于中断原因。宽限期并不保证每个请求都能继续。

- **机房 ASN 阻断（`blockDatacenterASN`）**：默认关闭（`P05` 命中机房或商业 VPN 时仅告警）；开启后，一旦检测到机房 ASN 或 ASN 缺测，门禁将直接 Fail-Closed 阻断。
- **CLI 配置目录隔离（`isolateClaudeConfigDir`）**：为当前档案分配独立 `CLAUDE_CONFIG_DIR`，隔离 `~/.claude.json` 中的 `userID`；多通道模式默认开启，传统单档案可按需开启或通过修复动作补齐。
- **遥测模式**：作用于受管路径。`s-cdn.anthropic.com` 风控信标始终走同源转发而不拦截；开启 `officialPrivacyFlags` 后仅拦停配置列表中的第三方遥测。配置中另有企业云模式枚举值，某家提供方的完整集成情况需要单独核实。字段细节见[配置项参考](/ClaudeBar-docs/zh/reference/configuration/)。

## 核验后启动一次

对当前档案运行检查，查看仍待处理的结果与「实时防护收据」，确认未触发跨档案同内核并号提示（`H17`）后，再从经过核验的入口启动。确认这次新开的受管会话确实使用了预期设置；原来打开的浏览器窗口可能属于别的会话。
