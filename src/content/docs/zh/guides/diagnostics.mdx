## 先确认查的是当前档案

打开工作台的 **检查与修复**，看清当前档案再重新检查。也可以在命令行运行同类检查。

```sh
swift run claudebar-cli probe --json
```

这条命令会在当前环境执行实时探测。它可能访问网络端点、读取档案凭据，并更新本地诊断记录。确认需要探测实际出口后，再在已配置好的环境中运行。

## 状态告诉你该查哪一步

| 状态 | 这次检查发生了什么 | 下一步 |
| --- | --- | --- |
| `PASS` | 观测结果符合这项检查的通过条件 | 在该项检查的覆盖范围内继续 |
| `MITIGATED` | 已有补偿措施覆盖这项问题，原来的状况仍可能存在 | 看具体是哪项措施在起作用 |
| `FAIL` | 取得了观测结果，但结果未达到通过条件 | 处理检查指出的原因，再跑一次 |
| `UNOBSERVED` | 这次没拿到观测结果 | 检查连通性，或查是哪一步没采到结果 |
| `SKIPPED_BLOCKED` | 某个前置条件没满足，这项检查没有运行 | 先处理前置条件 |

严重程度单独判断。关键检查失败，或关键观测缺失且没有补偿措施时，门禁可能拦截连接。

## 改设置前，找到最先出问题的地方

把预期条件和实际观测结果放在一起看。核对这项结果来自当前档案、历史事件，还是从受管流程之外启动的会话。接着看建议修复会改动什么、影响多大。

诊断会先跑前置检查，再查下游服务提供方。如果后面的检查被跳过，服务提供方是否正常、是否可达仍待确认。

## 需要别人协助时，先审阅诊断包

下面的命令生成供诊断代理读取的压缩包。导出也会运行实时检查。

```sh
swift run claudebar-cli export-bundle ./diagnostics.claudeguard.zip
```

导出时会做脱敏。分享前仍要打开压缩包检查内容，确认原始账号信息、代理凭据和私有会话内容都已去除。[安全边界](/ClaudeBar-docs/zh/concepts/security/)
