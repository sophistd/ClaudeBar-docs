## 先说结论：工具能隔离本地环境，但不保证“防封”

ClaudeBar 的工作是管住**本机受管出口**、**本地会话数据目录**和**启动前后的状态核验**。它无法替你改写服务商的风控规则，也不能承诺账号不会被限制、要求验证或停用。

建立正确预期最直接的办法，是先把**工具能管住的**和**工具管不住的**拆开来看。

## 划清边界：ClaudeBar 能管住什么，管不住什么

| 维度 | ClaudeBar 能管住的 | 工具管不住的 |
| --- | --- | --- |
| 网络出口与漂移 | 受管路径的 Fail-Closed 回环门禁；多源比对发现出口国家分裂或 IP 漂移时拦截启动或隔离会话 | 代理节点本身属于机房、商业 VPN 或已被污染的 IP（`P05` 可告警或按开关阻断，但不能把机房 IP 变成住宅 IP） |
| 暗道与本地泄露 | 启动参数与本地探针覆盖远端 DNS、IPv6 旁路、UDP STUN 和 QUIC（宿主若存在公网 IPv6 或裸 UDP 穿透，如实标为参数缓解而非抓包实证） | 未接入受管路径的其他本机应用或手动直连窗口 |
| 环境一致性 | 按出口国家对齐 `TZ` 时区与 `LANG` / `LC_ALL` / 浏览器语言；启动受管进程前剥离宿主的污染环境变量 | 账号长期行为模式、异常频率或服务商侧人工复核 |
| 会话与设备目录 | 浏览器 Cookie 与本地存储目录隔离；CLI 独立 `CLAUDE_CONFIG_DIR`（隔离 `~/.claude.json` 里的 `userID`）；Desktop 独立数据目录（隔离 `ant-did`） | **同一浏览器内核**下多 Profile 或多沙箱共享约 74/79 项硬件与图形渲染指纹 |
| 本地审计与自愈 | 零唤醒只读审计 `P15`（容器冲突）与 `P19`（`userID` / `ant-did` 跨档案及宿主碰撞），所有本地标识仅存 SHA-256 哈希；提供可回滚的受控修复 | 支付卡与 Stripe Radar 关联、邮箱/手机号规范化关联、Persona / Yoti 身份核验，以及 Sift 全网信誉图谱 |

## 多账号隔离阶梯：按风险从低到高选

如果你手上有多个 Claude 账号，不要把“换了个浏览器 Profile”当成“换了一台设备”。按隔离扎实程度从高到低，优先顺序如下：

1. **一机一号（物理零共享）**
   - 隔离最彻底的基线。不同账号落到不同物理设备上，硬件、图形栈、系统字体、本地存储和网络环境天然不交集。
2. **日常优先走隔离后的 CLI**
   - 写代码或日常对话优先使用受管并开启 `CLAUDE_CONFIG_DIR` 隔离的 Claude Code CLI。CLI 交互不经过 Web 浏览器里的 Sift `s.js` 指纹脚本采集面，同时每个档案拥有独立的 `userID` 与本地配置目录，并由 `P19` 检查是否与宿主默认目录或其他档案发生串号。
3. **Web 必须单机多号时：强制跨浏览器内核（一核一号）**
   - 如果确实需要在同一台 Mac 上登录多个 Web 账号，给每个账号分配**不同浏览器内核族**的浏览器，例如一个用 Chromium 系（Chrome、Edge、Brave 或 Aside），另一个用 Gecko 系（Firefox 或 Zen），再有需要可配合系统 WebKit（Safari）。
   - 跨内核能从渲染管线、WebGL/Canvas 输出、字体枚举和运行时特征这一层，大幅减少浏览器安装级指纹重合。
4. **严禁同一浏览器内核开多 Profile 或多沙箱登不同 Web 账号**
   - 不要在同一个 Chrome 里建多个 Profile，也不要拿同一套 Chrome 派生多个 `--user-data-dir` 独立沙箱去登不同账号。它们只隔开了 Cookie 和缓存，**没有**隔开 Web 端风控看到的浏览器安装与硬件渲染指纹。

> 同一账号在多个浏览器里打开（例如自己同时在 Chrome 和 Safari 用同一个号）属于正常单人使用。ClaudeBar 在跨档案分析中确认属于同一 `accountUUID` 时，不会把它误判为多号并号风险。

## 为什么不只是“一个被封连累另一个”？

很多人以为多账号共用同一个 Chrome，只要每个号都规规矩矩用、不出违规，就不会出事。这个直觉漏掉了两类完全不同的风控机制：

- **被动连坐（关联图谱传导）**：当同一个设备指纹、同一出口 IP 或同一张支付卡下有某个账号触发封禁或高危标记时，关联图谱上的其他账号很容易被一并波及。
- **主动计数加分（`users_per_device_id`）**：即便名下所有账号都在正常对话、目前一个都没有违规，Sift 风控系统在设备维度上观测到“同一套稳定设备指纹下先后登录了多个不同用户”，`users_per_device_id` 计数本身就会直接抬高风险分。

在同一个 Chromium 内核里切 Profile 或另开 `--user-data-dir`，Sift `s.js` 采集的约 79 项特征里，仍有约 74 项硬件、屏幕、图形渲染与内核特征保持不变。所以“换了 Cookie 目录”既挡不住事后连坐，也挡不住平时就被持续计入同设备多号。

## 为什么 ClaudeBar 不做 JS 指纹伪装，也不屏蔽 `s-cdn.anthropic.com`？

这两件事是 ClaudeBar **刻意不做**的，原因很直接：

- **不做 UA / Canvas / WebGL 等 JS 指纹伪装**：Sift 客户端内置自动化与环境一致性反篡改校验。往页面注入脚本强行改写 Canvas 噪点、伪造 User-Agent 或篡改 Navigator 属性，很容易留下前后矛盾的篡改痕迹，反而比真实环境更容易触发异常标记。要减少单机多 Web 号的指纹重合，应该老老实实走上文的隔离阶梯（优先一机一号或隔离 CLI，Web 迫不得已再跨内核），而不是靠“改指纹插件”。
- **不拦截 `s-cdn.anthropic.com`**：访问 `claude.ai` 时，页面会经由 `s-cdn.anthropic.com`（CNAME 指向 Sift）上报风控信标。如果用防火墙或广告屏蔽插件粗暴拦截，容易导致信标缺失或触发诱饵异常。ClaudeBar 的做法是把这条连接纳入受管出口，让它与主站走**同一条干净代理线路**（同源收口），仅在开启 `officialPrivacyFlags` 隐私模式时按配置拦停 Sentry、Datadog、Segment 等第三方遥测。

### 关于 Sift 的隐私敞口提醒

登录 `claude.ai` 后，每次切换对话页面，浏览器都会向 Sift 明文发送当前完整 URL（含对话 UUID）、对话标题开头以及账户 UUID（相关哈希字段为不加盐 MD5，不具备匿名化效果）。不要把密钥、令牌、真实姓名或敏感项目代号放进对话标题里。

## 在 ClaudeBar 里怎么核对和落地？

1. **查看「实时防护收据」**：在总览或通道详情页核对三件事——宿主污染变量是否已剥离、Sift 信标是否与主站同源转发、当前指纹隔离等级是否出现了跨档案同内核告警（`H17`）。
2. **盯紧三项核心探针**：
   - `P15`（跨档案隔离）：拦截不同档案共用同一个 Cookie / 数据容器。
   - `P19`（永久设备标识绑定）：只读校验 CLI `userID` 与 Desktop `ant-did`，防止串号或落回宿主默认目录。
   - `P05`（ASN 纯净度）：识别常见机房与商业 VPN 出口；如果你要求遇到机房 IP 或 ASN 缺测就硬拦截，可在对应档案或通道开启 `blockDatacenterASN`。
3. **管好工具之外的账号卫生**：不同账号使用彼此独立的支付卡、邮箱与手机号（避免 `+` 别名、加点变体或高度相似的连号前缀）；新建沙箱 24 小时内的冷启动期，避免密集注册或绑卡。
