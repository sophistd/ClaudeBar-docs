## 1. 选一个配置档案

启动应用，从菜单栏面板点 **Workbench**（工作台），再点侧栏底部的 **Settings**（偏好设置），打开「系统偏好与档案」。

选一个现有档案，或点 **新建隔离档案**，起个一眼能认出的名字。用应用里的代理导入入口添加有权使用的上游代理。报问题或分享截图时，请把实际使用的代理凭据留在本机。

如果手上是一条分享链接，先看[配置档案](/ClaudeBar-docs/zh/guides/configuration/)，判断能否直接导入，还是需要本地代理内核转接。

## 2. 选浏览器和会话模式

打开 **浏览器**，选择已安装的浏览器和受支持的会话模式。

- **单独打开**会使用独立的浏览器数据目录。
- **用现有登录**会打开浏览器已有的原生会话。ClaudeBar 不会向浏览器注入门禁的代理设置。

如果界面提示多个会话共用同一个容器，先解决冲突。

## 3. 先核验出口，再启动

先用工作台菜单的 **视图 → 重新核验出口** 检查一下。也可以在 **浏览器** 页点 **核验后打开登录**，让应用先做检查，再打开浏览器登录流程。

如果没有采集到观测结果，先查缺在哪一步。如果某项结果阻止启动，应用会打开 **检查与修复**，在那里打开对应条目，看实际观测到了什么。

## 4. 确认开的是这次会话

- 当前选中的是你打算使用的档案和对应浏览器。
- 受管线路的门禁状态是 **出口已放行**（`ARMED_OPEN`）。
- 没有仍在阻止启动的严重失败，也没有会阻止启动且缺少补偿措施的观测缺口。

原生模式下，「出口已放行」只反映门禁本身的状态。浏览器的实际线路与网络隔离要另行确认。已经打开的浏览器窗口也可能来自别的会话。要核对实例和数据目录，见[会话隔离](/ClaudeBar-docs/zh/concepts/sessions/)。

## 启动仍被拦截时

先让会话保持停用或隔离。到[查看诊断结果](/ClaudeBar-docs/zh/guides/diagnostics/)定位卡住的检查，再按[恢复会话](/ClaudeBar-docs/zh/guides/recovery/)处理。保留原来的检查条件，修好导致拦截的原因后再核验。
