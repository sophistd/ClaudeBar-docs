## ClaudeBar 能管住什么？

本机回环门禁管理接入它的受管连接。按当前已核对源码，ClaudeBar 在本地和受管路径上实现以下控制：

- **受管出口 Fail-Closed 门禁**：启动前经独立探测通道校验出口，记录出口基线；观测到多源国家分裂、IP 漂移或关键观测缺失时阻断放行或隔离会话。
- **暗道防护与环境对齐**：覆盖远端 DNS、IPv6 旁路、UDP STUN 与 QUIC 的启动参数及本地探测（若宿主仍存在公网 IPv6 或裸 UDP 穿透，诊断会如实标注参数缓解而非出网抓包实证），并将时区（`TZ`）与语言（`LANG` / `LC_ALL` / 浏览器语言）对齐出口国家。
- **本地会话与设备目录隔离**：在受支持的浏览器沙箱中隔离 Cookie 与本地存储目录；为 CLI 隔离 `CLAUDE_CONFIG_DIR`（含 `~/.claude.json` 的 `userID`），为 Desktop 隔离独立数据目录（含 `ant-did`）。
- **本地只读审计与受控自愈**：通过 `P15`、`P19` 等零唤醒只读探针检查跨档案容器冲突与设备标识碰撞（本地仅存 SHA-256 哈希，不落明文），并提供带快照与回滚日志的修复。
- **同源转发风控信标，不做 JS 指纹伪装**：ClaudeBar 刻意不屏蔽 `s-cdn.anthropic.com`，也不注入任何 UA / Canvas / WebGL 伪装脚本，而是将风控信标与主站一同走受管干净出口，仅在开启隐私模式时按配置拦停第三方遥测。
- **诊断包脱敏**：导出诊断包时自动做脱敏处理。

## 哪些事项工具管不住，也不作承诺？

上述机制来自源码核对，不是独立安全认证，更**不构成“防封”承诺**。以下事项超出 ClaudeBar 的控制范围或缺乏验证证据：

- **同浏览器内核的多 Profile 硬件与图形指纹重合**：在同一 Chromium 内核下切换子 Profile 或另开 `--user-data-dir` 沙箱，只隔离了 Cookie 与本地存储，Web 端 Sift 采集的约 74/79 项硬件、渲染与内核特征依然一致。详细分级见[多账号隔离与风控边界](/ClaudeBar-docs/zh/guides/multi-account-isolation/)。
- **代理节点本身的出口属性**：如果上游代理本身是机房、商业 VPN 或已被污染的 IP，ClaudeBar 无法把它变成干净住宅 IP（`P05` 可告警，开启 `blockDatacenterASN` 可硬阻断）。
- **服务商账号与支付风控图谱**：支付卡与 Stripe Radar 关联、邮箱/手机号规范化关联、Persona / Yoti 身份核验、Sift 全网信誉图谱，以及服务商是否允许某个账号继续使用服务。
- **未接入受管路径的本机流量**：门禁不自动覆盖本机每一个进程和每一个数据包；可选系统扩展与包过滤需另行取得权限、签名、公证并激活，本版文档未对其作实机验证。

ClaudeBar 用于合法的网络配置、会话管理和诊断。使用服务时仍须遵守服务商的条款和账号规则。

## 哪些本地数据与外部上报需要留意？

配置档案保存设置和凭证引用。按设计，代理密码等敏感凭证由系统钥匙串保存，规范化的代理配置里只保留引用；设备标识绑定记录只存 SHA-256 哈希。本地诊断记录及历史仍可能暴露环境细节。

界面遮盖账号只是为了避免直接显示，数据并未因此加密。诊断包虽然经过脱敏，分享前仍需检查内容。请勿公开真实的配置档案存储、浏览器数据目录、账号标识或签名材料。

登录 `claude.ai` 后，每次切换对话页面都会向 Sift 明文发送完整 URL（含对话 UUID）、对话标题开头与账户 UUID，请勿在对话标题中留存密钥、令牌或真实姓名。

## 输入的文本会发到哪里？

发送前的提示词检查可以启用云端环节。使用该环节时，文本可能会发送给所配置的服务商。提交机密内容前，请确认选中的服务商和实际启用的流程。

这个文档站只提供静态内容，没有 AI 聊天功能，也不会调用模型服务。

## 如何报告安全问题？

请通过获取源码访问权限或应用构建包时使用的私下渠道联系维护者。公开文档议题中请勿发布凭证、私密诊断数据或漏洞利用细节。截至本次源码核对，项目没有已确认的公开漏洞报告邮箱。

ClaudeBar 是独立项目，与 Anthropic 无隶属关系，也未获其背书。
