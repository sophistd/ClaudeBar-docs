## 一次受管连接怎么出去

ClaudeBar 的门禁在本机回环地址上接受受支持的 HTTP CONNECT 和 SOCKS5 连接。启动前检查通过后，ClaudeBar 把观测到的出口身份记为**出口基线**。门禁进入放行状态后，受管连接可以通过配置好的上游代理访问网络。

<div class="flow" role="img" aria-label="受管应用通过本机回环门禁连接到配置好的上游代理"><span>受管应用</span><b aria-hidden="true">→</b><span>本机回环门禁</span><b aria-hidden="true">→</b><span>上游代理</span></div>

转发链路只传送隧道里的字节，无需安装 TLS 拦截证书。门禁的覆盖范围限于接入这条链路的连接。

## 上游断了一下，门禁怎么处理？

<GateExplorer />

演示从启动前检查成功之后开始。它省略了应用中的短暂探测状态 `PREFLIGHT_PROBING`，也没有真实的计时器、网络套接字和探测调度。配置档案默认给门禁 **4 秒宽限期**。可以分别操作演示里的两个「到期」选项，看看有探测拒绝和没有观测结果时会发生什么。

| 状态 | 新连接握手 | 接下来会怎样 |
| --- | --- | --- |
| 停止 `STOPPED` | 门禁尚未启用 | 先核验出口，再启用门禁 |
| 放行 `ARMED_OPEN` | 可以获得放行许可 | 链路中断时可以进入宽限期 |
| 暂缓 `GRACE_HOLD` | 等待恢复 | 出口身份匹配就恢复。实测漂移就立即隔离。到期时按探测结果处理 |
| 隔离 `TRIPPED_ISOLATED` | 拒绝握手 | 查看事件记录，重新核验出口 |

### 宽限期到期有两种结果

- **没有新观测结果，也没有记录到恢复探测被拒绝**。门禁沿用旧的出口基线，恢复放行。这次恢复没有重新核验出口。
- **记录到恢复探测被拒绝，直到到期仍未恢复**。门禁进入隔离状态。若此前已测到出口身份不匹配，门禁会立即隔离，无需等到到期。

首次启动要先拿到通过核验的出口基线。沿用基线只适用于已经启用的门禁。

宽限期主要让新握手等待。旧隧道能否继续使用，要看中断原因。网络切换和系统休眠可以立即断开旧隧道。普通的上游代理短时中断可以保留旧隧道，因此正在处理的请求能否继续，取决于触发条件。

### 怎样算出口身份匹配？

恢复时，出口的国家或地区必须和基线一致。有可用的 ASN（自治系统编号）证据时，ASN 也要匹配。配置档案默认开启严格固定 IP，此时还要求出口 IP 一致。关闭严格固定 IP 后，如果缺少可用的 ASN 证据，仍须核对出口 IP。

探测通过说明这一次观测符合条件。其他应用可能走不同路径。排查失败请求时，也要区分是目标服务拒绝请求，还是连接根本到不了上游代理。
