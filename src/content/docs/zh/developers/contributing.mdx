## 确定内容放在哪里

- **教程**（`Tutorial`）带读者走完一次学习过程，并给出明确的完成标准。
- **操作指南**（`How-to`）围绕一件具体的事，写清前提和步骤。
- **参考**（`Reference`）供人查具体参数、语法和行为。
- **原理说明**（`Explanation`）解释系统为什么会这样运行。

每页在 frontmatter 中填写受众、前提、预期结果和证据状态。中文版与英文版共用同一套内容字段，`kind` 仍使用对应的英文枚举值。

## 在浏览器里验证改动

```sh
npm ci
npm run verify
npx playwright install chromium
npm run test:browser
```

搜索索引随生产构建生成，先构建再查搜索。检查 GitHub Pages 基础路径、站内锚点、小屏布局、浅色与深色主题，以及能否用键盘完成操作。浏览器自动扫描可补充人工无障碍检查，完整的 WCAG 合规仍需要单独验证。

## 发布前核对范围

文档仓库只放专为公开编写的内容和文档站实现。应用源码、内部计划、发布二进制、真实诊断包、个人路径、账号信息和凭据都应留在原有的私有渠道。发布新内容前，更新发布清单。

报告产品行为时，通过合适的私有维护渠道提供可复现的证据。公开的文档 issue 只放可公开的信息。
