## Launch and interruption

Preflight gathers evidence for the selected launch path. Once verified, ClaudeBar gives the managed process its route configuration. When upstream conditions change, incident and diagnostic evidence inform the next action. Use the [gate model](/ClaudeBar-docs/concepts/network-egress/) to compare holding, recovery, and isolation.

## Data and entry points

Versioned profiles retain settings, credential references, session bindings, and history. Observations inform diagnostic reports and repair plans. The native interface coordinates these operations; the CLI exposes selected workflows without requiring the workbench.

## Optional system controls

The application includes system-extension and packet-filter integration paths. They are separate from the ordinary loopback proxy path and require their own deployment and privilege checks. Do not infer that they are active because the application is running.

## Developer boundary

The package separates core domain logic, a gate library, the native interface, and executable entry points. Consult [repository architecture](/ClaudeBar-docs/developers/architecture/) when changing behavior. Public docs describe supported operating concepts; internal engineering plans are not part of this site.
