## What each part does

Think through one launch. A **profile** holds your settings. Probes check the current conditions and establish an **egress baseline**. The **gate** uses the verified baseline when admitting and recovering managed connections.

<DocFigure src="/ClaudeBar-docs/diagrams/architecture-en.svg" alt="System layers from profile and storage through observation and decisions to runtime control and managed connections." width={780} height={348} />

<details>
<summary>How the work is divided</summary>

The macOS interface coordinates the layers. Some operations can also run through the CLI. The configured upstream proxy carries connections that enter the loopback gate. Optional system controls have their own deployment and permissions. See [architecture](/ClaudeBar-docs/concepts/architecture/) and [security boundaries](/ClaudeBar-docs/concepts/security/).

</details>

## Which route the browser takes

Both routes can start with an egress check. The difference comes after that check. A **guarded sandbox** starts a supported browser instance with its own data directory and the gate proxy configured. A **native session** opens the existing browser with its existing network configuration.

<DocFigure src="/ClaudeBar-docs/diagrams/routes-en.svg" alt="The guarded browser is configured to use the loopback gate. The native browser follows its existing route after an egress comparison." width={780} height={326} />

<details>
<summary>What a matching egress check establishes</summary>

Before opening a native session, ClaudeBar compares the host and gate egress. A match tells you what the check observed at that moment. It does not establish the route of later browser traffic. ClaudeBar does not inject the gate proxy into the native browser, so closing the gate alone does not establish that the browser is offline. See [session isolation](/ClaudeBar-docs/concepts/sessions/).

</details>

## What happens after an interruption

Once the gate is armed, a short interruption can start a **grace window**. New handshakes wait while the gate checks whether it can resume.

<DocFigure src="/ClaudeBar-docs/diagrams/recovery-en.svg" alt="An armed gate enters a grace window. Matching egress resumes admission, drift isolates immediately, and expiry depends on whether a probe was rejected." width={780} height={330} />

Expiry without a new observation or recorded rejection reuses the existing baseline. This recovery does not reverify the egress.

<details>
<summary>What happens to new and existing connections</summary>

A profile defaults to a four-second grace window. The wait applies to new handshakes. Existing tunnels can close immediately for some interruptions, such as sleep or a network switch. An ordinary upstream interruption can leave existing tunnels in place. Use the [interactive gate model](/ClaudeBar-docs/concepts/network-egress/) to compare the outcomes.

</details>

## Where to look in the macOS app

App screenshots use demo data, not live network results. Controls retain the app’s Chinese labels.

### Menu bar panel

Use **嗅探** (discover) to look for local proxy settings. **主工作台** opens the workbench.

<DocFigure src="/ClaudeBar-docs/screenshots/menu-panel-firstrun-light.png" alt="First-run menu bar panel with the Discover button at top right and the workbench entry along the bottom." width={712} height={660} kind="screenshot" />

### Overview

Open **总览** to see the selected profile and the gate’s egress status. Check **正在跑** to see how the app classifies each running instance.

<DocFigure src="/ClaudeBar-docs/screenshots/workbench-overview-light.png" alt="Overview with the selected profile, egress state, separate browser launch button and a list of unmanaged browser instances." width={2080} height={1360} kind="screenshot" />

### Checks and repair

Open **检查与修复**. Read the summaries along the top, then use the risk map on the left and the individual check results on the right to investigate. See [how to read diagnostics](/ClaudeBar-docs/guides/diagnostics/).

<DocFigure src="/ClaudeBar-docs/screenshots/workbench-topology-light.png" alt="Checks and repair workbench with an egress summary, a risk map and an individual check results list." width={2080} height={1360} kind="screenshot" />

### Content preflight

**内容预检** examines supplied text. This is a different preflight from the network checks used to arm the gate. The workbench shows text analysis stages, highlighted input and risk categories. A configured cloud stage may send supplied text to a model provider.

<DocFigure src="/ClaudeBar-docs/screenshots/workbench-preflight-light.png" alt="Content preflight with analysis stages across the top, sample text on the left and risk categories on the right." width={2080} height={1360} kind="screenshot" />
