## Platform

The package declares macOS 14 or later and Swift tools version 6.2. This documentation work ran on an Apple silicon Mac with Swift 6.4.2; the CLI build and 25 selected fixture tests passed. Intel runtime behavior and a macOS version matrix were not tested here.

## Browser model

| Browser family / known entries | Mode represented by the implementation | Important constraint |
| --- | --- | --- |
| Pure Chromium: Chrome, Edge, Brave | Guarded sandbox or native session | Installed-app detection must confirm capability |
| Wrapped Chromium: Arc, Dia, Aside | Native session | Do not assume Chromium launch flags or separate data-directory support |
| WebKit: Safari | Native session | Chromium command-line routing is unavailable |

This table describes code-supported modes. It is not a certification of every current browser release. Subprofile routing is limited to engines whose installed descriptor supports it.

## Proxy import versus transport

| Input | Parsing support | Direct gate use |
| --- | --- | --- |
| HTTP CONNECT | Yes | Supported after verification |
| SOCKS5 / SOCKS5H | Yes | Supported through the SOCKS path |
| HTTPS upstream proxy | Yes | Requires a local bridge; no silent TLS downgrade |
| Shadowsocks, VMess, VLESS, Trojan, Hysteria2, TUIC share formats | Yes | Encrypted remote transport requires a local core bridge |
| Supported Clash YAML entries | Yes | Depends on the resulting transport |

A loopback bridge must itself be configured and running. ClaudeBar's parser does not install a third-party network core.

## System-level controls

System-extension code exists, but a local build alone does not grant entitlements or OS activation. Packet-filter controls involve elevated permissions and affect a different boundary from an ordinary loopback listener. Neither was activated or tested during documentation work.
